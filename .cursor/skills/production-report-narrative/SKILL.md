# 生产运营汇报的内容组织

版式和配色是 `exec-visual-system` 的事，这里只管**说什么、按什么顺序说**。

材料做得再漂亮，如果没回答管理层真正关心的问题，仍然是一次失败的汇报。

## 管理层只关心四个问题

任何生产运营汇报，本质是回答这四个问题，顺序不能变：

| 顺序 | 问题 | 常见错误 |
|---|---|---|
| 1 | **结果怎么样？** 达成了没有，差多少 | 上来先讲过程和工作量 |
| 2 | **为什么？** 归因到可干预的因素 | 归因到"市场原因""客观困难"（无法干预等于没归因） |
| 3 | **风险在哪？** 什么会让下期继续恶化 | 只报喜不报忧，风险藏在附录 |
| 4 | **需要什么决策？** 明确到人、钱、时间 | 结尾写"谢谢聆听"，没有请求 |

**没有第 4 项的汇报是浪费会议时间。** 如果这次汇报确实不需要决策，就在开头说明
"本次为进展同步，无需决策"，让听众切换到正确的收听模式。

## 结论先行

第一页正文（封面之后）必须是执行摘要，包含：

```
一句话总判断      产量超目标 5.2 个百分点，但 3 号线瓶颈已开始制约三季度交付
3-4 个核心 KPI    总产量 / 达成率 / 一次通过率 / 重大偏差
三个结论          每条一句话，粗体结论 + 一行灰色解释
需要决策的事项    2-3 条，每条明确金额/人数/时间
```

后面的章节是这一页的展开和论证。**如果领导只看第一页就够了，说明这一页做对了。**

不要把结论放在最后一页"总结"里。管理层的注意力在前三分钟最集中，会议经常在讲到
一半时被打断或跑题。

## 行动标题

每一页标题必须写结论，不能写栏目名。这是整份材料里性价比最高的改动。

| 栏目名（弃用） | 行动标题（采用） |
|---|---|
| 上半年产量情况 | 产量同比增长 23%，超年度目标 5.2 个百分点 |
| 质量指标分析 | 质量指标全面改善，来料波动是当前最大风险源 |
| 3 号线运行情况 | 3 号线是唯一未达标产线，缺口 8.4 个百分点 |
| 下一步工作计划 | 优先投自动结晶控制系统，投资回收期 14 个月 |
| 关于人员配置的说明 | 关键岗位缺员 12 人，9 月前不补齐将影响 Q4 排产 |

写法：**主语 + 变化/状态 + 量化程度**，能加"所以呢"就更好。
一句话说不完就说明这页装了两个结论，应该拆成两页。

## 归因要落到可干预因素

归因分析的价值在于指向行动。检验标准：**这个原因是我们能改的吗？**

| 无效归因 | 有效归因 |
|---|---|
| 市场需求波动 | 客户 A 的订单在 5 月集中释放，排产未预留缓冲，需调整滚动预测周期 |
| 设备老化 | 3 号线结晶釜换热面积不足，降温段耗时占批次周期 38% |
| 人员经验不足 | 结晶降温依赖人工判断，8 名操作工中仅 3 人有 2 年以上经验 |
| 供应商问题 | 两家原料供应商纯度波动 ±1.8%，来料放行标准未覆盖该指标 |

归因层次做到能定位到具体工序、具体设备、具体标准缺失，最好带量化占比
（如"结晶周期偏长占缺口影响的 52%"）。

## 指标体系

下表是医药 CDMO / 精细化工生产管理的常用指标。**需核实**：具体口径、目标值、
统计边界必须按本企业实际管理体系确认，不要直接套用。汇报中的每个指标都要能说清
"分子是什么、分母是什么、数据从哪个系统取"。

### 产能与交付

| 指标 | 口径要点 |
|---|---|
| 产量 | 注明单位（吨 / kg）和是否折纯 |
| 产能利用率 | 实际产出 / 设计产能，注明是否扣除计划检修 |
| 计划达成率 | 实际产出 / 计划产出，注明计划是年初版还是滚动版 |
| 按时交付率 OTIF | 按承诺交期完成的订单占比 |
| 生产周期 CT | 从投料到放行，还是到出货，口径差别很大 |
| 批次周转数 | 单位时间完成批次数，反映排产效率 |

### 质量与合规

| 指标 | 口径要点 |
|---|---|
| 一次通过率 RFT | 无返工无偏差直接放行的批次占比，最能反映体系稳定性 |
| 偏差数量 | 必须区分重大/次要，只报总数没有意义 |
| CAPA 关闭及时率 | 按期关闭数 / 应关闭数 |
| OOS / OOT | 数量 + 调查关闭及时率 |
| 返工率 / 报废率 | 批次口径还是数量口径要注明 |
| 客户投诉 | 数量 + 响应及时率 |
| 客户审计 / 监管检查 | 发现项数量、分级、关闭情况 |
| 变更控制 | 按期关闭率 |

### 成本与效率

| 指标 | 口径要点 |
|---|---|
| 收率 Yield | 摩尔收率还是重量收率，注明 |
| 单位制造成本 | 是否含折旧、是否分摊期间费用 |
| 物料利用率 / 溶剂回收率 | 回收率提升直接影响成本和环保指标 |
| 单位能耗 | 吨产品耗电 / 耗蒸汽 |
| 人均产值 | 分母是在岗人数还是含外协 |

### EHS

| 指标 | 口径要点 |
|---|---|
| 可记录事故率 / 损失工时事故 | 按标准工时基数折算 |
| 隐患上报数与闭环率 | **上报数上升往往是好事**（说明愿意报），要和闭环率一起看 |
| 未遂事件数 | 同上，是领先指标 |
| 危废产生量与合规处置率 | — |
| 三废排放达标率 | — |
| 安全培训完成率 | 完成率 vs 有效性是两件事 |

安全类汇报要特别注意：**隐患上报数下降不等于更安全**，可能是上报意愿下降。
把"上报数"和"整改闭环率""重复隐患占比"放在一起才能看出真实状况。

### 设备

| 指标 | 口径要点 |
|---|---|
| OEE | 可用率 x 性能率 x 良品率，三个分量要能拆开看 |
| 非计划停机时长 | 按次数和总时长双维度 |
| PM 完成率 | 预防性维护按期完成 |
| 关键设备可用率 | 先定义什么是关键设备 |
| 计量校准按期率 | 合规相关 |

### CDMO 项目维度

| 指标 | 口径要点 |
|---|---|
| 在手项目数与阶段分布 | 临床前 / I-III 期 / 商业化，反映未来收入结构 |
| 技术转移成功率 | 首批即达标的项目占比 |
| 首批成功率 | 新项目首批一次通过 |
| 工艺验证批完成情况 | PV 批次进度 |
| 客户审计通过率 | — |

**客户信息一律代号化**（"A 客户""项目 M"），即使是内部汇报。

## 领先指标与滞后指标

只报滞后指标（产量、事故数、投诉数）的汇报没有前瞻性 —— 数字出来时已经无法干预。
每个重点领域配一个领先指标：

| 领域 | 滞后指标 | 领先指标 |
|---|---|---|
| 质量 | 偏差数、投诉数 | 一次通过率趋势、关键参数 CPK、来料合格率 |
| 交付 | 按时交付率 | 排产饱和度、瓶颈工序在制品、物料到位率 |
| 安全 | 事故数 | 隐患上报与闭环、未遂事件、行为观察合规率 |
| 设备 | 非计划停机 | PM 完成率、关键备件库存、振动/温度趋势 |
| 成本 | 单位成本 | 收率趋势、溶剂回收率、能耗强度 |

## 汇报类型的结构模板

### 月度 / 季度经营汇报（8-14 页）

```
封面
执行摘要（结论 + KPI + 三个结论 + 决策事项）
01 整体表现     产量趋势、达成率、产线负荷
02 质量与合规   核心质量指标表、偏差趋势、审计情况
03 EHS          事故与隐患、闭环率
04 瓶颈与改善   问题定位、改善进展、量化效果
05 下一步       里程碑计划 + 资源需求
结尾：需要决策的事项
```

### 专题汇报 / 立项（6-10 页）

用 SCQA 展开：

```
情境 Situation   现状与背景，双方共识的事实
冲突 Complication  发生了什么变化 / 出现了什么问题
问题 Question    因此我们要回答什么
答案 Answer      建议方案（先给结论）
—— 以下是论证 ——
问题定位与量化（瓶颈在哪、影响多大）
方案对比（2-4 个方案的投入 / 收益 / 风险，用四象限或对比表）
推荐方案的实施路径与里程碑
投资回报测算与敏感性
风险与应对
需要批准的事项
```

方案对比**必须包含"维持现状"这一项**并量化其代价，否则决策者无法判断投资的必要性。

### 事故 / 重大偏差汇报（5-8 页）

```
事件概要（时间、地点、级别、影响范围、是否已受控）
时间线（发现、上报、处置、恢复各节点时刻）
根本原因分析（5Why 或鱼骨图，要穿透到管理系统层面）
影响评估（质量影响、批次处置、客户影响、合规影响）
纠正与预防措施 CAPA（措施、责任人、完成时间、验证方式）
同类风险排查结论（其他产线/工序是否存在同样问题）
```

关键：**根本原因不能停在"操作人员未按 SOP 执行"**。要继续问为什么 SOP 没被执行 ——
是 SOP 不可操作、培训不到位、还是考核机制导致的抢产量。停在员工层面的分析没有
预防价值，而且管理层一定会追问。

### 复盘总结（年度 / 项目）

```
当初的目标是什么（原始承诺，不要事后修改）
实际结果是什么（对着目标逐项打分）
差异原因（做对了什么、做错了什么）
可复用的经验（具体到可执行的做法）
下一周期的改变（不是"加强管理"，而是具体机制变更）
```

## 数据呈现的规矩

- **每个数字都要能溯源。** 页脚写清系统名和统计区间："数据来源：MES 系统，
  2026-01-01 至 2026-06-30"。管理层追问数据来源时答不上来，整页可信度归零。
- **同比、环比、对目标，至少给一个参照。** 孤零零一个"产量 1,284 吨"无法判断好坏。
- **区分百分比和百分点。** 从 95% 到 97% 是"上升 2 个百分点"，说"上升 2%"会被纠正。
- **口径变更必须显式说明。** 统计范围、计算方式一旦调整，在页面上注明，否则会被
  当成数据造假。
- **不要用平均值掩盖分布。** "平均达成率 101%"可能掩盖了某条产线只有 78%。
  该拆开的必须拆开。
- **异常值要主动解释。** 图上那个突然的低点，你不解释，领导一定会问。
- **没有归因数据时，把异常写成待跟踪项，不要编原因。** "6 月闭环率回落 1.3pp，
  已列入 7 月跟踪" 是诚实且有用的；硬写一个猜测的原因，一旦被追问就崩了。

## 交付前自查

- [ ] 第一页看完能知道结论和要决策什么吗
- [ ] 每页标题是结论还是栏目名
- [ ] 有数字的页都写了数据来源吗
- [ ] 归因是否落到可干预因素、有量化占比
- [ ] 风险和坏消息是否放在正文而非附录
- [ ] 决策事项是否明确到金额、人数、时间、责任方
- [ ] 是否准备好回答"这个数为什么是这样""为什么不选另一个方案"
- [ ] 客户和产品信息是否已代号化
- [ ] 是否标注了密级
