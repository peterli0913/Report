# 高层汇报视觉系统

这个 skill 提供**视觉决策的依据**。具体怎么写代码见 `exec-deck-builder`（PPT）
和 `html-exec-report`（网页）。

## 一条总原则

**高层汇报的视觉设计目标不是好看，是让人在 20 秒内抓住结论。**

管理层看一页的时间通常不超过半分钟，而且经常是隔着会议桌看投屏。所有取舍都服从
这一点：能删的都删，剩下的都放大，重点只留一个。

判断一页做得好不好，就问三个问题：

1. 遮住标题，还能一眼看出这页要说什么吗？（看不出 → 视觉层次没建立）
2. 这页的重点是唯一的吗？（有两个重点 = 没有重点）
3. 后排的人能看清最小的那行字吗？（看不清 → 删内容，不是缩字号）

## 视觉层次：靠对比，不靠装饰

层次感来自**尺寸对比**，不来自加线、加框、加渐变。可用的手段按优先级：

| 手段 | 做法 | 强度 |
|---|---|---|
| 字号 | 重点比正文大 2-3 倍（如 40pt vs 14pt） | 最强 |
| 留白 | 重点周围留出大片空白 | 很强 |
| 色块 | 重点用饱和色块承载 | 强 |
| 颜色 | 重点用强调色，其余降为灰 | 中 |
| 粗细 | 加粗 | 弱 |

字号对比不敢拉开，是汇报页显得平庸的最常见原因。标题 23pt 配正文 14pt 是有效对比；
标题 16pt 配正文 14pt 等于没有层次。

## 配色

### 结构：一主、一辅、一强调

- **一个主色占 60-70% 视觉重量**（通常是底色或大面积色块）
- **1-2 个辅助色**用于图表序列和次级色块
- **一个强调色只给全篇最关键的数字和结论**

强调色用超过 3 处，它就不再是强调色。这是最容易犯的错。

### 语义色必须固定含义

| 含义 | 用途 | 注意 |
|---|---|---|
| 达成 / 改善 | 绿 | — |
| 需关注 | 黄 / 橙 | — |
| 未达成 / 风险 | 红 | 慎用：一页出现三处红色就变成"到处都是问题" |
| 中性 / 对照 | 灰 | 历史值、对照组、非重点项一律降灰 |

**"下降"不等于"坏"。** 能耗、偏差数、投诉量、事故数下降是好事，必须显式指定绿色，
不能让工具按箭头方向自动配色。这是生产管理汇报里最常见的配色错误。

### 深色底还是浅色底

| 场景 | 选择 | 理由 |
|---|---|---|
| 会议室投屏汇报 | 深色底 | 环境光暗，深底不刺眼，数字更醒目 |
| 需要打印或传阅 | 浅色底 | 深底打印费墨且发灰 |
| 附在邮件/OA 里被随手翻 | 浅色底 | 小屏、亮环境下浅底更易读 |
| 想要沉稳、贵重、有分量 | 深色底 | — |

不确定就用深色底做正式汇报版、浅色底做打印版。`deckkit` 换 `theme="light"` 即可，
其余代码不动。

### 对比度是硬性要求

正文与背景对比度不低于 **4.5:1**，18pt 以上的大字不低于 **3.0:1**（WCAG AA）。

这不是设计洁癖 —— 投屏的实际对比度远低于显示器，浅灰字在会议室里会直接消失。
`deckkit` 会自动按亮度选文字色，`check_deck.py` 会把不达标的报为 error。

关键认识：**填充色和文字色是两回事**。饱和的绿做色块很好，当成小字压在深底上就
不够读。所以语义色要各准备两个版本。

### 凯莱英品牌色（从现有模板提取）

以下色值取自仓库中 `安全专篇1页.pptx` 的 `ppt/theme/theme2.xml`，是你们**现有模板
实际在用**的颜色：

| 角色 | 色值 | 来源字段 |
|---|---|---|
| 主色深蓝 | `#003669` | dk1 |
| 次级蓝 | `#3263A7` | dk2 |
| 强调金 | `#E5B620` | accent2 |
| 图表蓝 | `#4472C4` `#5B9BD5` `#2AA9DB` | accent1/5/6 |
| 深蓝紫 | `#2649AB` | accent3 |
| 亮金 | `#FFC000` | accent4 |
| 浅文字 | `#E7E6E6` | lt2 |
| 警示红 | `#C00000` | 正文实际用色 |
| 中文字体 | 微软雅黑 | — |
| 西文字体 | Arial | — |

**需核实**：以上是从模板反推出的实际用色，不一定等于集团 VI 手册的标准色值。正式
对外材料请向品牌/市场部门确认官方 CMYK/RGB 规范。

`deckkit` 的默认深色主题已按这套色调设计（底色 `#0A1F3C`、强调金 `#E5B620`）。
要严格贴合模板原色：

```python
from deckkit import DARK, Deck
T = DARK.variant(bg="003669", bg_alt="002A52", surface="0B4880",
                 surface_alt="3263A7", ink="E7E6E6", primary="4472C4",
                 secondary="2AA9DB", accent="E5B620").with_readable_text()
deck = Deck(theme=T, canvas="large")   # large = 26.67x15，与现有模板同尺寸
```

`.with_readable_text()` 按新底色重算全部语义文字色 —— **不能省**。底色一变，原本
达标的绿/红/灰就可能掉到 4.5:1 以下。

**但它有代价，必须验收。** 底色越亮，文字色为了凑够 4.5:1 就得越亮，红/橙/绿会一起
被推向淡彩，"绿=达成、橙=关注"的语义就失效了 —— 这正好废掉本节前面强调的语义配色。
所以改完主题必须跑两项检查：

```python
from deckkit import audit_theme
for p in audit_theme(T):      # 空列表才算过
    print(p)
```

`audit_theme()` 同时查两件事：每个文字色在每档底色上的对比度，以及语义色两两之间的
色差够不够读者分辨。**报"色差不足"时，正确做法是把 `surface` / `bg` 调暗，而不是
继续凑文字色** —— 在偏亮的底色上，饱和的红色文字物理上无法达到 4.5:1。

然后照常跑 `check_deck.py` 并看渲染图，确认绿和橙一眼能分开。

## 中文排版

中文排版和西文的规则不一样，照搬西文经验会出问题。

### 字体

| 用途 | 推荐 | 说明 |
|---|---|---|
| 正文（Windows） | 微软雅黑 | Office 自带，字重适中，投屏清晰 |
| 正文（跨平台） | 思源黑体 / Noto Sans CJK | 开源，多字重 |
| 标题 | 与正文同族的加粗 | 中文不要混搭两种字体，容易脏 |
| 数字 | Arial / Helvetica | 中文字体的数字字形偏窄且不整齐 |
| 避免 | 宋体、楷体、幼圆、艺术字体 | 投屏笔画发虚，或过于随意 |

**关键技术点**：写 pptx 时必须同时设置西文字体（`<a:latin>`）和东亚字体（`<a:ea>`）。
只设前者的话中文会回落到主题字体，这是"我明明设了字体却没生效"的根因。
`deckkit.apply_font()` 已处理。

字体名由**打开文件的机器**渲染。对外发送的材料要么用 Office 自带字体（微软雅黑、
Arial），要么导出 PDF。

### 字号与行距

投屏汇报的基准（13.333 x 7.5 英寸画布）：

| 层级 | 字号 |
|---|---|
| 封面主标题 | 36-44pt |
| 章节标题 | 30-36pt |
| 页面标题 | 22-26pt |
| KPI 大数字 | 36-54pt |
| 小节标题 | 15-17pt |
| 正文 | 14-16pt |
| 图表标签、脚注 | 9-12pt |

**正文 14pt 是下限。** 装不下就拆页或删内容 —— 缩字号只是把"信息太多"这个问题
藏起来，投屏后依然读不了。

中文行距用 **1.25-1.35 倍**。西文常用的 1.5 倍在中文下会显得段落松散、行与行失去
关联；1.0 倍则因为汉字字面率高而显得拥挤。

如果画布是 26.67 x 15（双倍尺寸，国内企业模板常见），所有字号乘 2。`deckkit` 用
设计单位自动换算，不用手算。

### 标点与混排

- 中文用全角标点（，。；：），不要用半角逗号句号。
- 中英文之间、中文与数字之间留一个空格：`产量 1,284 吨`、`使用 MES 系统`。
  这是排版惯例，能明显提升可读性。
- 数字加千分位：`1,284` 不是 `1284`。
- 单位和数字之间留空格，单位用小一号字并降灰。
- 百分点和百分比要区分：从 95% 到 97% 是"上升 2 个百分点"，不是"上升 2%"。
  汇报里混用会被追问。

### 对齐

- **正文和列表永远左对齐。** 中文居中的段落每行起点都不同，眼睛找不到行首。
- 只有封面主标题、章节标题、表格中的状态列适合居中。
- **表格数字列一律右对齐**，否则位数对不齐、没法快速比较大小。
- 同类元素严格对齐：三张卡片的标题必须在同一水平线上。

## 版式选择

| 要表达 | 用什么版式 |
|---|---|
| 整体表现总览 | KPI 大数字卡一行 3-4 个 |
| 时间趋势 | 折线或分组柱状，配一句结论条 |
| 多项目排名比较 | 横向条形（类目名长时必须横向） |
| 构成占比 | 堆积条形；只有 2-4 项时用环形图 |
| 多指标 vs 目标 | 达成率条组（起点对齐才能比较） |
| 改善前后 / 方案对比 | 左右对比块 |
| 优先级、风险分级 | 2x2 四象限 |
| 计划与里程碑 | 时间轴 |
| 精确数值对照 | 表格（配语义色标出达成情况） |
| 一句话结论 | 通栏结论条，全页唯一 |

### 页面留白

- 页边距不小于画布宽度的 4%（13.333" 画布上约 0.55-0.65"）
- 元素间距 0.24-0.5"，同一份材料里只用 2 档间距，别每处都不一样
- **一页正文控制在 300 字以内**，超过 420 字就该拆页
- 宁可多一页，不要挤一页。翻页的成本远低于读不懂的成本

## 让材料显得廉价的特征

这些是典型的"模板感"和"AI 味"，逐条避免：

| 特征 | 为什么廉价 | 改成 |
|---|---|---|
| 标题下加一条装饰横线 | 最典型的模板痕迹 | 用留白或底色分隔 |
| 通栏色条、单边色边框、侧边竖色条 | 纯装饰，不承载信息 | 卡片底色微调 + 阴影 |
| 每页版式一模一样 | 单调，听众会走神 | 交替使用卡片、图表、对比、表格 |
| 纯文字 + 一堆 bullet | 没有视觉锚点 | 每页至少一个图表/大数字/色块 |
| 三维图表、阴影渐变柱子 | 扭曲数据比例 | 用平面图表 |
| 饼图超过 5 个扇区 | 读不出大小差异 | 换横向条形 |
| 到处都是强调色 | 重点被稀释 | 全篇强调色不超过 3 处 |
| 每页都写"谢谢聆听" | 浪费一页 | 结尾页写要对方决策什么 |
| 文字被裁掉、元素重叠 | 显得不认真 | 交付前必须跑质检 + 看渲染图 |
| 拉伸变形的照片 | 非常显眼 | 按比例裁剪，不要拉伸 |

## 一页要素清单

内容页的完整结构（按位置从上到下）：

```
栏目标签（eyebrow）  ← 交代这页在结构中的位置，小字、强调色
行动标题             ← 把结论写进标题，不是写栏目名
——————
主体内容             ← 图表 / 卡片 / 表格，一页一个重点
结论条（可选）        ← 一句话结论，全页唯一
——————
数据来源              ← 有数字就必须写         页码
```

缺 `eyebrow` 听众会迷失在长汇报里；缺数据来源会被追问；标题写成栏目名，这页就
浪费了最值钱的位置。
